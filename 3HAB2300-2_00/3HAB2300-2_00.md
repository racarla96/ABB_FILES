# 3HAB2300-2/00 — S4 Program Update

**Program no.:** 3HAB2300-2/00
**Name on disk label:** S4 Program Update
**Date:** May 14, 1995
**Type:** MS-DOS PC tool (not a robot boot disk)

## What this tool does

This is an official ABB tool (1995, for MS-DOS) that solves a very specific floppy-disk logistics problem.

### The problem it solves

Each robot has a unique serial number (e.g. `IRB6400-0187`). Every boot floppy belonging to THAT robot has this serial number recorded inside it (in the binary tail of `disc.id`). When ABB released a new revision of a program (e.g. going from `3HAB2317-1/05` to `3HAB2317-1/13`), they couldn't manufacture a separate floppy with the correct serial number for every one of the thousands of robots installed worldwide. Instead, they manufactured "generic" floppies of the new revision with **no serial number at all** (blank serial) — as they are, the controller rejects these disks; they won't boot on any robot.

### What `UPDATE.EXE` does

It's a program you run on a regular PC (with a floppy drive) to "personalize" those generic disks before taking them to the robot:

1. You insert an **original** disk from your own robot (the old version that already works) → the program reads its serial number.
2. You insert the new (generic, blank) disk → the program **copies that same serial number** into its binary tail, and also tells you to write it by hand on the label.
3. Repeat for each disk of the new revision.
4. Result: a set of disks for the new revision, already "authorized" with your robot's serial number, ready to boot on it.

## Package contents (as uploaded)

- `README.TXT` — the tool's own description (matches the explanation above).
- `INSTALL.BAT` — simple installer, copies `UPDATE.EXE` to `c:\s4prog\`.
- `UPDATE.EXE` — MS-DOS executable (~40 KB), compiled with Borland C++.
- `disc.id` — this disk's own id file; decodes with an **empty serial** (expected: this disk is the installer itself, not meant to be booted into a robot controller).

## Menu options (from `UPDATE.EXE` strings)

1. Authorize revision boot disk(s) — the main function described above.
2. Identify any boot disk — reads and displays Program No / Boot Disk / Serial No of any disk, without comparing or modifying anything.
3. Delete the update program — uninstalls itself from `c:\s4prog\`.
4. Help
5. Exit

## Cross-check against the robot-side format

Disassembly of `UPDATE.EXE` (x86 16-bit) shows two routines that decode the serial from the disk's binary tail using the exact same formula already reverse-engineered from the robot's `ABB_MC` firmware (68k):

```
decoded_byte[i] = (tail_byte_at(POS[i]) + 0xA7 - 2*i) & 0xFF
```

looping for up to 17 characters, stopping at a decoded `0`, and skipping `(17 - i)` bytes after each read — matching the `POS[i]` stepping already documented. One of the two routines (used by "Authorize") also compares the decoded value character-by-character against the `Serial no` text in the disk's ASCII header, exactly like the self-consistency check already implemented in `make_discid.py check`.

This independently confirms the format: the same algorithm appears twice in ABB's own code, on two different CPU architectures (68k on the robot, x86 on this PC tool).
